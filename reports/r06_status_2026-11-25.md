길이 붕괴 없음 (run3 와 r05 와 다름). 틀린 샘플이 약간 길어지는 쪽.

**Tunix GRPO loss 집계**: `sequence-mean-token-mean`.
- 기본값: `tunix/rl/grpo/grpo_learner.py:85` (`loss_agg_mode: str = "sequence-mean-token-mean"`), `tar_rlvr/train/grpo.py` 의 `GRPOConfig(...)` 에서 지정 안 함.
- 계산: `tunix/rl/common.py:560–565` — 시퀀스마다 토큰 loss 를 그 시퀀스 길이로 나눈 평균 → 배치에서 시퀀스 평균.
- 길이 편향: **있다.** 토큰 하나의 gradient 가중치가 1/|o| 라 긴 시퀀스일수록 토큰당 신호가 작다 (Dr. GRPO 가 지적한 편향). 틀린 샘플(advantage < 0)에서는 긴 completion 이 토큰당 덜 억제된다. 그림 샘플은 시각 토큰 81개 + bridge 15토큰 + 이어쓰기가 붙어 길기 때문에, **틀린 샘플 중 그림이 있는 쪽이 덜 벌받는다.** 맞힌 샘플에서는 반대로 짧은 쪽이 토큰당 더 강화된다. 관찰된 그림 사용률 상승 (advantage 는 0 근처인데도) 을 설명하는 후보 중 하나.

**bridge 토큰은 loss 에 포함된다 (마스킹 안 됨).**
- `tar_rlvr/train/continuation.py:107`: `seq = 1차 토큰 + bridge_ids + 2차 토큰` 을 completion 으로 합친다.
- `tunix/rl/grpo/grpo_learner.py:256`: `completion_mask = np.not_equal(padded_completion_ids, pad_value)` — pad 만 제외.
- → bridge 문장(모델이 생성하지 않은 강제 토큰)과 시각 토큰 모두 정책 gradient 를 받는다. bridge 는 모델 샘플이 아니므로 off-policy 토큰에 on-policy 가정(ratio=1)을 적용하는 셈.

- **거짓 양성 0 / 거짓 음성 0.** 객관식에서 값으로 답한 경우도 보기와 맞게 채점됨 (예: `-2` = 보기 C, `[0,8]` = 보기 B, `2` = 보기 A ≠ 정답 D).
- reward=0 중 1개는 "Answer:" 다음에 다시 그림을 그려 답이 그림 토큰 (redraw).
- **채점은 맞지만 보상 신호가 노이즈**: reward=1 10개 중 최소 3개 (`Answer:A` 계획만 쓰고 계산 없음, `C` 근거 무관, `[0,8]` 앞 단계 계산 틀림) 는 근거 없이 맞은 답. 그림 completion 의 21–25% 는 bridge 뒤에 `=` 가 하나도 없는 "계획만" 형태.

## 8. 판정

- **파라미터는 움직이고 있지만, 정답률이 오른다는 증거는 없다.** eval sampled pass@1 은 step 0 대비 Δ ≈ 0 (±0.07). greedy 0.24 → 0.29 는 McNemar p = 0.42. 학습 정답률도 base passrate 를 넘지 못한다.
- **분명히 변한 건 그림 사용뿐이다** (eval greedy 0.61 → 0.80–0.91). 그런데 같은 그룹 안에서 그림 샘플이 더 맞히지 않고 (+0.003 [−0.07, +0.08]), advantage 도 0 이다. 그림 사용 증가는 정답 보상이 아니라 sequence-mean 길이 편향이나 bridge 토큰 학습에서 왔을 가능성이 높다. 이건 아직 검증하지 않은 가설이다.
- **가장 큰 교란 요인**: 학습 데이터의 56% 가 4지선다다. 관찰된 정답률 (객관식 0.245) 이 찍기 수준 (0.25) 과 같고, 맞은 샘플 상당수가 근거 없는 정답이다. 이 상태에서는 보상의 대부분이 운이고, eval (객관식 52%, 32 프롬프트 pass@1) 도 같은 노이즈에 묻힌다.
- **판단력을 가장 크게 올릴 변경 하나**: 객관식을 학습과 eval 양쪽에서 빼고 (또는 보기를 숨기고 값으로 답하게 하고), eval 을 held-out 100 전체 × 8 샘플 pass@1 로 바꾼다. 비용이 늘면 eval 간격을 50 step 으로 늘린다. 그래야 0.05 수준의 변화를 구분할 수 있다.
- **지금 시점 결론: "모르겠다"에 가깝고, 정답률 쪽은 '아니오'에 가깝다.** 300 step 을 다 돌려도 이 설정에서는 판별이 어렵다.
